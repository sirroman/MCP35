# 🔒 Безопасность

Документ описывает два механизма защиты MCP **на стороне 1С** (работают при прямом
подключении к HTTP-сервису, без Node-обёртки `index.mjs`):

1. **Кто может пользоваться сервисом** — авторизация по имени пользователя ИБ / праву.
2. **Какие инструменты разрешены** — политика доступа к инструментам (allow/deny).

Оба механизма задаются **прямо в коде** `Module.bsl`; изменение требует правки модуля и
обновления конфигурации. Это осознанный выбор: настройки не редактируются из пользовательского
режима и не могут быть изменены через сам MCP.

> ⚠️ Гейты в коде — **не замена правам пользователя 1С**. Инструменты исполнения кода
> (`execute_code`, `evaluate_expression`, `call_function`, `call_object_method`) в пределах прав
> пользователя могут делать что угодно. Обязательно используйте отдельного пользователя
> `mcp_agent` с минимальными правами — это единственная стойкая граница.

## 1. Кто может пользоваться MCP (авторизация)

Без ограничений HTTP-сервис MCP доступен **любому** аутентифицированному пользователю ИБ.
Это, в частности, превращает эндпоинт в онлайн-оракул для **подбора паролей** любого
пользователя базы (см. ниже). Ограничение задаётся в функции `ДоступКСервисуРазрешён()`.

Работают две независимые проверки (пустой критерий = отключён):

| Критерий | Настройка в коде | Что делает |
|----------|------------------|------------|
| Белый список имён | `РазрешённыеПользователи` | пропускает только перечисленных пользователей ИБ |
| Обязательное право | `ОбязательноеПраво` | требует у пользователя право конфигурации (напр. `"Администрирование"`) |

```bsl
Функция ДоступКСервисуРазрешён()
        // === Настройка ===
        РазрешённыеПользователи = Новый Массив;
        РазрешённыеПользователи.Добавить("mcp_agent");   // ← ваши имена пользователей ИБ

        ОбязательноеПраво = "";   // напр. "Администрирование"; пусто = проверка по праву отключена
        // =================
        ...
КонецФункции
```

Неавторизованный вызов получает ошибку `-32001 «Доступ к MCP запрещён для текущего пользователя»`.

### ⚠️ Про перебор паролей — что этот гейт решает, а что нет

Basic Auth проверяется платформой 1С **до** запуска нашего кода. Поэтому:

- Гейт в коде **ограничивает, что может сделать** аутентифицированный пользователь, и не даёт
  чужой (даже валидной) учётке пользоваться MCP. Это резко сокращает радиус поражения.
- Но он **не останавливает сам перебор паролей**: по коду ответа (`200` при верном пароле vs
  `401` при неверном) атакующий всё равно видит, что пароль угадан, ещё до нашей проверки.

Реальная защита от перебора — на уровне инфраструктуры:

- Отдельный пользователь `mcp_agent`, длинный случайный пароль.
- **Обратный прокси** перед сервисом: rate-limit, блокировка по IP, allowlist адресов.
- Только **HTTPS**; по возможности — сетевая изоляция эндпоинта.
- Запрет инструментов-перечислителей (`get_active_users`, `get_rights_for_user`,
  `execute_query` по `Справочник.Пользователи`) — они помогают собрать список логинов для атаки.

## 2. Политика доступа к инструментам (allow/deny)

Задаётся в `ПолучитьПолитикуИнструментов()` и `ОпасныеИнструментыПоУмолчанию()`:

- **`Режим = "deny"`** — разрешено **всё, кроме** списка (чёрный список, по умолчанию);
- **`Режим = "allow"`** — разрешено **только** то, что в списке (белый список).

Гейт действует в трёх точках:

| Точка | Поведение при запрете |
|-------|-----------------------|
| `tools/call` (основной диспетчер) | ошибка JSON-RPC `-32601` |
| `execute_batch` (подвызовы) | исключение — нельзя вызвать в обход |
| `tools/list` | запрещённые инструменты **не видны** в списке |

Список по умолчанию (группа HIGH):

```
execute_code, evaluate_expression, call_object_method, call_function,
delete_object, delete_extension, load_extension, run_scheduled_job,
run_data_processor, import_data, execute_batch, assign_role_to_user
```

### Как менять политику

Правьте `ОпасныеИнструментыПоУмолчанию()` (список имён) и `Режим` в `ПолучитьПолитикуИнструментов()`.

**Пример — строго «только чтение» (allow):**
```bsl
// В ПолучитьПолитикуИнструментов(): Режим = "allow"
// В ОпасныеИнструментыПоУмолчанию() оставить только читающие инструменты:
Список.Добавить("get_metadata_tree");
Список.Добавить("get_object_metadata");
Список.Добавить("execute_query");
Список.Добавить("get_object_by_ref");
Список.Добавить("get_list");
Список.Добавить("find_by_code");
Список.Добавить("find_by_name");
Список.Добавить("get_register_records");
Список.Добавить("get_document_list");
Список.Добавить("get_balance");
Список.Добавить("get_related_documents");
Список.Добавить("get_form_structure");
Список.Добавить("get_rights");
Список.Добавить("find_duplicates");
```

**Пример — операционный сценарий (чтение + запись, без кода и админки, режим `deny`):**
оставить в чёрном списке `execute_code`, `evaluate_expression`, `call_object_method`,
`call_function`, `delete_object`, `delete_extension`, `load_extension`, `run_scheduled_job`,
`run_data_processor`, `import_data`, `execute_batch`, `assign_role_to_user` — запись документов
и справочников при этом останется доступной.

## ✅ Как проверить

1. Синтаксический контроль модуля в Конфигураторе.
2. Вызов под неразрешённым пользователем → ошибка `-32001`.
3. `tools/list` → запрещённых инструментов нет.
4. Прямой вызов запрещённого инструмента → ошибка `-32601`.
5. `execute_batch` с запрещённым подынструментом → отклоняется.

## 🧷 Смежные меры

- **HTTPS** — Basic Auth передаёт логин/пароль в base64.
- **Отдельный пользователь `mcp_agent`** с минимальными ролями.
- HTTP-сервис в Конфигураторе желательно держать **непривилегированным**, чтобы права
  пользователя реально ограничивали инструменты.
- Обратный прокси с rate-limit / IP allowlist перед эндпоинтом.
